## Revisión completa de workflows

Se inspeccionaron los seis workflows activos y todos sus invocadores:

- `pr.yml`: PR abiertas, actualizadas o reabiertas y lanzamiento manual; token de
  lectura, cancelación de ejecuciones anteriores de la misma referencia.
- `relay-ci.yml`: `push main` y manual; token de lectura. No se cancela una
  ejecución de main ya iniciada para reemplazarla por la siguiente.
- `ci.yml`: reutilizable, jobs independientes para análisis, lint y tests. Mantiene
  los nombres de los checks existentes y añade validación de workflows y build.
  Bundler usa lockfile congelado y el entorno declara UTC.
- `mobile-ci.yml`: filtros de cambios web/móvil relevantes, token de lectura,
  concurrencia por referencia y sin herencia de secrets.
- `flutter-build.yml`: Java 17, Flutter 3.32.4 fijo, análisis, tests y APK debug
  para CI ordinario. Firma APK/AAB disponible solo en ejecución manual de main.
- `pipelock.yml`: historial completo para comparar diffs, token de lectura,
  credenciales de checkout no persistidas, timeout y cancelación por referencia.

No hay un workflow activo de despliegue, publicación de imagen o TestFlight.
Los archivos de `docs/archive/sure/workflows/` son material histórico, no
automatizaciones ejecutables. El nuevo build no publica imágenes ni despliega.

Los siete SHA de acciones se contrastaron con sus etiquetas: checkout 7.0.1,
setup-node 7.1.0, upload-artifact 7.0.2, setup-ruby 1.329.0, setup-java 6.0.1,
flutter-action 2.23.0 y Pipelock 3.6.0. Coinciden; Pipelock usa una etiqueta
anotada cuyo commit resuelto es `3e868ac5…`.

Se conservan las cachés administradas por setup-ruby y setup-node; los jobs
aislados comparten dependencias, no un directorio de trabajo mutable. npm
restaura descargas y vuelve a instalar con el lockfile. No se añaden claves
manuales amplias ni cachés de credenciales. GitHub restringe el acceso entre
ramas y referencias de PR; las cachés de main pueden ser legibles desde forks,
por lo que no deben contener secretos. Véase la [referencia de cachés de GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching).

Se mantienen jobs separados para no serializar los tests detrás del lint. La
instalación repetida de Bundler se amortiza con la caché; crear un artefacto de
gems compartido añadiría transferencia, permisos y más acoplamiento. No se han
introducido matrices de Ruby o de bases de datos que el producto no declare
soportadas. Screenshots de fallos: siete días; artefactos móviles: treinta días.

## Determinismo e aislamiento de tests

El inventario textual encontró 225 archivos de tests/fixtures con fecha actual
o fechas relativas y 109 con candidatos de generación aleatoria. Son candidatos
de revisión, no 334 fallos demostrados: muchos usan fechas relativas coherentes,
identificadores únicos o `travel_to`. No se afirma haber probado cada candidato
en todos los días del calendario.

Inventario reproducible: `rg -n 'Date.current|Time.current|[0-9]+\.(days?|months?|years?)\.ago' test -g '*.rb' -g '*.yml'`
y `rg -n 'SecureRandom|Faker|\.sample\b|rand\(' test -g '*.rb'`.
Las fixtures de tasas de hoy/ayer pueden colisionar con inserciones al comienzo
del mes; las de presupuestos/entradas deben leerse junto con el reloj del test.
Los `sample` de categorías operan sobre su lista válida y, al cambiar color,
excluyen el actual. Quedan sleeps anteriores en flujos de importación CSV y
transacciones; son candidatos a sustituir por condiciones del DOM en trabajo
posterior, no una explicación demostrada del fallo de ZIP.

Se revisaron los fixtures financieros, el helper compartido, informes,
backtesting, tests de importación, usos de `sample`, sleeps y modificaciones de
locale. Se conservan las transacciones de fixtures y el reseteo por prueba de
`Setting.clear_cache`, que evita contaminación de su caché en memoria. Los tests
de onboarding restauran el locale. VCR/WebMock y cassettes siguen siendo la vía
de pruebas de proveedores; no se han agregado llamadas externas financieras.

Las pruebas de corte ahora cubren seis combinaciones de calendario y mes
familiar, además del historial vacío. No se congela globalmente el reloj porque
alteraría los contratos de otras fixtures y de tests que hacen su propio viaje
temporal. Se conserva el orden aleatorio; se documentan las semillas ejecutadas.

## Límites y pendientes

- Protección de `main`: la integración devuelve **403 Resource not accessible
  by integration**. El endpoint de rulesets devuelve una lista vacía; eso no
  prueba que no exista protección clásica. La configuración de permisos y
  aprobación de Actions no pudo consultarse mediante el conector. No se cambió
  ninguna política. Un administrador debe comprobar required checks y aprobación
  de PR externas. Los nuevos jobs no pasan a ser required checks por sí solos.
- Las 38 omisiones locales existentes siguen siendo deuda de cobertura. Varias
  suites de cifrado exigen configuración explícita, aunque Rails tenga claves de
  test. CI ordinario no certifica esa variante. También quedan omisiones de i18n
  y funcionalidades heredadas; no se presentan como controles superados.
- PostgreSQL/Redis fijan familia, no digest; apt y los runners siguen recibiendo
  parches. Mantener Chrome for Testing fijo exige actualizarlo periódicamente.
  Importmap/npm audit y las descargas de herramientas dependen de servicios
  externos; sus fallos ahora bloquean en lugar de producir un falso verde.
- Se conservan las exclusiones preexistentes de Pipelock para ejemplos y locales
  y `test-vectors: false`. Las exclusiones amplias merecen revisión separada; no
  se ampliaron para esta auditoría. La prueba local verificó checksum, no firma
  Sigstore. El código de la acción admite verificación de firma si hay Cosign.
- Firma release APK/AAB, iOS/TestFlight y despliegues reales no se ejecutaron:
  no son parte de la validación sin credenciales ni del alcance autorizado de
  despliegue. Se verificó la compilación debug y el build de producción Rails.

La separación de mocks de Minitest 6 está documentada en su [historial oficial](https://github.com/minitest/minitest/blob/v6.0.0/History.rdoc).
Las variables para resolver navegador y driver se contrastaron con la
[documentación de Selenium Manager](https://www.selenium.dev/documentation/selenium_manager/).
